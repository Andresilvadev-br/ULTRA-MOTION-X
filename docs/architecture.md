# Architecture

Ultra Motion X separates **motion computation**, an **intermediate representation** and
**presentation**. The same specification is implemented once in Rust (shared by every native
host and by WebAssembly) and once in TypeScript for the DOM runtime, where calling into WASM
every frame would cost more than it saves. Cross-implementation conformance vectors
(`tests/conformance/vectors.json`, generated by the Rust code) keep both in agreement to 1e-9.

## Key design decisions

- **Analytic generators.** Springs, decay and inertia are evaluated in closed form as a pure
  function of elapsed time. Results do not depend on frame rate, any instant can be queried
  (scrubbing, Time Machine), and retargeting reuses the exact position and velocity.
- **Fixed-step simulation** for systems without closed forms (coupled springs, worlds,
  particles): `FixedStepper` runs an integer number of identical steps regardless of the
  display rate. Transcendentals go through the pure-Rust `libm`, so native results are
  bit-reproducible across operating systems for a given build.
- **One owner per property** with explicit priorities and interruption policies
  (`replace`, `queue`, `reject`, `additive`). Gestures outrank decoration.
- **On-demand frame loop.** The web engine and the native runtime request frames only while
  something animates; idle gaps are excluded from telemetry.
- **Compositor where it helps.** Opacity (and, on request, full transforms) can be baked into
  Web Animations; batches larger than `compositorMaxElements` stay on the frame loop because
  baking costs main-thread time (see performance.md).
- **No silent writes.** All integration changes are planned, previewed, applied as
  transactions and reversible without destroying later user edits.
